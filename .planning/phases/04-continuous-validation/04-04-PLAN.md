<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LHCI runner → filesystem (.lighthouseci/) | LHCI writes JSON reports — content is performance data, no untrusted input |
| CI runner → origin/main (via git push) | GITHUB_TOKEN with contents: write; commit message controls workflow re-trigger |
| .lighthouserc.json → LHCI behavior | Config change shifts upload destination from public storage to local filesystem |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04-01 | Denial of Service | Recursive CI loop from LHCI commit | mitigate | D-13: `[skip ci]` enforced in both commit messages; verified via regex assertion in Tasks 3 and 4 |
| T-04-04-02 | Information Disclosure | LHCI report contains URLs/scores | accept | URLs are public (`https://mentoria.sertaoseracloud.com/deep-dive-vm/`); scores are non-sensitive |
| T-04-04-03 | Elevation of Privilege | contents: write granted to lighthouse job | mitigate | Scoped to single job (test.yml) or single-job workflow (weekly); no PAT used; GITHUB_TOKEN auto-revoked at job end |
| T-04-04-04 | Tampering | LHCI JSON mutated between write and commit | accept | Single-runner job; no cross-job race; `git add .lighthouseci/` stages exactly what LHCI wrote |
| T-04-04-05 | Spoofing | Forked PR pushes to main | mitigate | test.yml commit step gated `if: github.ref == 'refs/heads/main'`; forks lack write token |
| T-04-04-06 | Information Disclosure | Previously: `temporary-public-storage` exposed reports on public GCP bucket | mitigate | D-11 removes this exposure by switching to local filesystem |
</threat_model>
