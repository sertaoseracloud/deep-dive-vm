<objective>
Replace LHCI's `temporary-public-storage` upload target with a local SQLite-backed LHCI server whose `lhci.db` file is committed back to `main` after each weekly run (per D-10, D-11, D-12). Provides historical Lighthouse score persistence without third-party services.

Purpose: Persistent LHCI score history queryable via the LHCI server UI; auditable trend data.
Output: `.lighthouserc.json` `upload.target` change, `@lhci/server` + `sqlite3` installed, `lighthouse-weekly.yml` extended with server start + lhci.db commit-back, fallback to filesystem target documented.

**Wave 2 rationale:** Depends on Plan 03 (the weekly workflow file must exist before we modify it to add server start steps).

**Implementation decision required (Task 0 below):** SQLite path requires `LHCI_BUILD_TOKEN` secret created via `lhci wizard`. If that prerequisite cannot be satisfied, the filesystem fallback (target: filesystem, outputDir: .lighthouseci) is applied instead — no server, no token, no commit-back. Both paths are documented; the executor decides based on Task 0 outcome.
</objective>
