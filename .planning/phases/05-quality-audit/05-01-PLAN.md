<task type="auto">
  <name>Tarefa 2: Inspeção manual sistemática e documentação do gate QUAL-01</name>
  <files>.planning/phases/05-quality-audit/QUAL-01-audit.md</files>
  <read_first>
    - src/layouts/Layout.astro (inspecionar: will-change nos blocos, data-reveal transition, data-stagger animation, hero-stagger-item)
    - src/components/HeroMotion.tsx (inspecionar: variants hidden/visible com opacity+y, HeroMotionSingle querySelectoreAll + classList.add em useEffect)
    - src/components/SettingsToggle.tsx (inspecionar: motion.span animate opacity, transition duration 0.2)
    - src/components/sections/Pricing.astro (inspecionar: price-card:hover will-change transform, reduced-motion reset para auto)
    - src/components/ui/Button.astro (inspecionar: btn:hover will-change transform, reduced-motion reset para auto)
    - impeccable-report.json (incluir no relatório)
  </read_first>
  <action>
    Inspecionar os 5 arquivos contra cada item do checklist de 5 pontos. Para cada arquivo, verificar:

    ITEM 1 — will-change scopado corretamente:
    - will-change: transform ou opacity DEVE aparecer apenas dentro de :hover, :focus, ou seletores de estado ativo
    - will-change fora desses contextos (ex: regra de classe simples sem pseudo-classe) = FAIL
    - Verificar: Layout.astro (nenhum will-change esperado no CSS global), HeroMotion.tsx (motion.div gerencia internamente), SettingsToggle.tsx (motion.span — Motion gerencia), Pricing.astro (.price-card:hover e reset em reduced-motion), Button.astro (.btn:hover e reset em reduced-motion)

    ITEM 2 — Sem layout thrashing em loops:
    - HeroMotion.tsx HeroMotionSingle: o useEffect faz forEach que lê targets.length e escreve style.animationDelay + classList.add — verificar se há leitura de offsetHeight/offsetWidth/getBoundingClientRect dentro do mesmo forEach (= thrashing). Apenas leitura de .length antes do loop = OK.
    - SettingsToggle.tsx: sem manipulação DOM direta, usa motion.span declarativo = OK
    - Layout.astro: CSS puro, sem JS = OK

    ITEM 3 — Propriedades compositor-friendly:
    - Animações usam opacity e transform (não top/left/width/height/margin) = PASS
    - Verificar: data-reveal usa opacity + transform translateY. data-stagger usa fade-up (opacity + transform). hero-stagger-item usa animação CSS. HeroMotion variants usam opacity + y (transform). motion.span usa opacity.

    ITEM 4 — prefers-reduced-motion respeita todas as animações:
    - Layout.astro: @media (prefers-reduced-motion: reduce) deve cobrir data-reveal, data-stagger, hero-stagger-item
    - HeroMotion.tsx: MotionConfig reducedMotion="user" no caminho A; HeroMotionSingle checa prefersReduced antes de aplicar classes
    - SettingsToggle.tsx: MotionConfig reducedMotion="user"
    - Pricing.astro: @media reduced-motion reseta will-change e transform para .price-card
    - Button.astro: @media reduced-motion seta will-change: auto e transition: none

    ITEM 5 — Sem will-change: contents (proibido — invalida todo o subtree):
    - Verificar que nenhum arquivo usa will-change: contents em qualquer regra

    Após inspeção completa, criar .planning/phases/05-quality-audit/QUAL-01-audit.md com:
    - Resultado por arquivo: PASS/FAIL por item do checklist
    - Resultado geral: PASS se todos os itens de todos os 5 arquivos passarem
    - Saída resumida do impeccable-report.json (zero findings ou lista dos findings tipográficos encontrados)
    - Decisão final: QUAL-01 PASS ou QUAL-01 FAIL com itens a corrigir

    Se algum item falhar, aplicar a correção mínima necessária no arquivo correspondente ANTES de documentar o resultado final. Exemplos de correções esperadas (com base no RESEARCH.md):
    - will-change fora de :hover → mover para dentro do seletor :hover correspondente
    - Leitura de propriedade de layout dentro de forEach de escrita → extrair leituras antes do loop (array de valores pré-calculados)
  </action>
