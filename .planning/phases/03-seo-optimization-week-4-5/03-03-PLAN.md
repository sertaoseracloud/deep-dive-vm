<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Google Fonts CDN | Inline onload JS executes in browser context; swaps rel attribute |
| Astro build pipeline → local PNG files | Local files processed at build time; no external input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03-01 | Tampering | `onload` inline JS in font preload link | accept | The `onload` attribute runs in the browser and only modifies the `rel` attribute of the same element; no user input, no XSS surface; no CSP is configured (per RESEARCH.md security domain analysis) |
| T-03-03-02 | Information Disclosure | WebP image URLs in `_astro/` | accept | The hashed filenames in `_astro/` are public build artifacts for a public landing page; no sensitive information in filenames |
| T-03-03-03 | Denial of Service | Google Fonts CDN unavailability | mitigate | `<noscript>` fallback ensures font CSS is still retrieved in no-JS environments; the preload+onload pattern degrades gracefully — system fonts render immediately if Google Fonts is slow or unavailable, then swap via `font-display: swap` |
| T-03-03-04 | Tampering | `src` prop type mismatch in `<Image>` | mitigate | `src` must receive `ImageMetadata` (raw import), not a string. Astro's TypeScript types will produce a type error at build time if `.src` string is passed. Verify by checking `npm run build` exits 0 without type errors. |
</threat_model>
