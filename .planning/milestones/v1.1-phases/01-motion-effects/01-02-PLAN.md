<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| isOpen prop → ARIA state | Parent-controlled boolean determines aria-hidden; incorrect wiring = invisible menu accessible to screen readers |
| motionEnabled (hook) → animate call | If hook reads stale value, animation may fire despite user preference |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | MobileMenuMotion aria-hidden | mitigate | aria-hidden={!isOpen} is derived directly from the isOpen prop — no intermediate state can desync it. |
| T-02-02 | Denial of Service | CarouselMotion infinite loop consuming CPU | mitigate | animation.pause() on mouseenter; animation.stop() on unmount cleanup; Lighthouse TBT < 50 ms gate in Wave 3. |
| T-02-03 | Information Disclosure | SSR rendering motion.nav with wrong initial state | mitigate | initial={{ x: "-100%" }} is the correct off-screen starting position; SSR outputs static markup that hydrates correctly on client. |
| T-02-04 | Elevation of Privilege | N/A — no auth boundaries in animation layer | accept | Animation components have no access to privileged data or APIs. |
</threat_model>
