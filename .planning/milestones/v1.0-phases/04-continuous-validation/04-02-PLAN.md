<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → GitHub repo (badges branch) | GITHUB_TOKEN writes to a branch — untrusted input is the coverage JSON content |
| GitHub repo (badges branch) → shields.io → README viewer | Public JSON served via raw.githubusercontent.com |
| CI commit messages → workflow triggers | `[skip ci]` token controls whether downstream workflows fire |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Denial of Service | CI loop from badge commit | mitigate | D-13: `[skip ci]` enforced in commit message; verified via grep gate in Task 2 acceptance |
| T-04-02-02 | Tampering | `badges` branch overwritten via force-push | mitigate | Step uses regular `git push` (no `--force`); branch protection optional |
| T-04-02-03 | Elevation of Privilege | Workflow gains broad write scope | mitigate | `permissions: contents: write` scoped at job level only, not workflow-wide |
| T-04-02-04 | Information Disclosure | Coverage % leak | accept | Coverage % is non-sensitive metadata |
| T-04-02-05 | Spoofing | Forked PR pushes to badges branch | mitigate | Step gated `if: github.ref == 'refs/heads/main'` — forks cannot reach this branch and lack write token |
| T-04-02-06 | Denial of Service | Empty coverable surface crashes badge script | mitigate | Guard `if (!json.total)` writes fallback `{message:"0%",color:"red"}` |
</threat_model>
