**Archived:** 2026-05-17
**Status:** Complete

## Business Requirements

### Core Objective

Transformar o site em uma plataforma multi-landing-page: a raiz `mentoria.sertaoseracloud.com/`
vira um hub Linktree-style otimizado para compartilhamento em redes sociais, e cada curso
vive na sua própria rota (`/deep-dive-vm/`, `/deep-dive-ec2/`, etc.).

### Constraints (invioláveis)

- NÃO alterar o conteúdo ou design visual da landing page Deep Dive VM existente ✅
- URL `/deep-dive-vm/` deve ser preservada (sem quebrar links externos) ✅
- Sem novas dependências de runtime — usar apenas o que já existe no projeto ✅
- CI/CD deve continuar verde após a migração (Vitest + Playwright + LHCI) ✅

- [x] **MIGR-01**: `astro.config.mjs` não possui a propriedade `base` — o site é servido da raiz
  com o domínio personalizado (`site: 'https://mentoria.sertaoseracloud.com'` permanece)
  **Outcome:** Satisfied — Phase 6 Plan 02. Verified in VERIFICATION.md.

- [x] **MIGR-02**: A landing page Deep Dive VM é acessível em `/deep-dive-vm/` via arquivo

- [x] **MIGR-03**: `public/CNAME` contém `mentoria.sertaoseracloud.com` — o arquivo é incluído
  em cada build e o domínio personalizado sobrevive a todos os deploys do GitHub Pages
  **Outcome:** Satisfied — Phase 6 Plan 01. Verified in VERIFICATION.md.

- [x] **MIGR-04**: Todos os caminhos hardcoded `/deep-dive-vm/` em `src/` estão corrigidos
  (favicon href em `Layout.astro:48`, JSON-LD `offersUrl` em `Layout.astro:16`), e os
  testes de CI estão atualizados (`playwright.config.ts` `baseURL` e `webServer.url`;
  `tests/seo/seo-meta.test.ts` path para `dist/deep-dive-vm/index.html`)
  **Outcome:** Satisfied — Phase 6 Plan 03. LHCI gate pre-existing tech debt (72% vs 80%).

## HUB — Página Linktree na Raiz

- [x] **HUB-01**: A página `src/pages/index.astro` exibe um hub com layout minimalista
  mobile-first contendo foto do mentor e bio (nome + frase de apresentação em 1-2 linhas)
  **Outcome:** Satisfied — Phase 7. 8/8 UAT tests passed in production.

- [x] **HUB-02**: O hub exibe cards dos cursos disponíveis, cada um com título, descrição
  curta e link — incluindo `/deep-dive-vm/` (ativo) e `/deep-dive-ec2/` (em breve)
  **Outcome:** Satisfied — Phase 7. Course cards verified in production and E2E.

- [x] **HUB-03**: O hub exibe links de redes sociais com ícones para Instagram, YouTube,
  WhatsApp e LinkedIn — configuráveis sem alterar estrutura de código
  **Outcome:** Partial — 3/4 active (Instagram, YouTube, LinkedIn). WhatsApp disabled
  pending real E.164 number. Accepted as tech debt for v1.3.

- [x] **HUB-04**: O hub possui meta tags Open Graph completas (`og:title`, `og:description`,
  `og:image` 1200×630px servida via HTTPS, `og:url`) gerando preview rico ao ser
  compartilhado no WhatsApp, Instagram e LinkedIn
  **Outcome:** Satisfied — Phase 7. OG verified via metatags.io in production UAT.

## SCAFF — Scaffold Multi-LP

- [x] **SCAFF-01**: A rota `/deep-dive-ec2/` existe e exibe uma página "em breve" simples —
  demonstrando o padrão de como uma nova landing page é adicionada ao projeto
  **Outcome:** Satisfied — Phase 8 Plan 01. Live at mentoria.sertaoseracloud.com/deep-dive-ec2/.

- [x] **SCAFF-02**: `HOWTO-new-landing-page.md` na raiz do repositório documenta o processo

  **Outcome:** Satisfied — Phase 8 Plan 03. 7 numbered steps, verified via grep.

## Future Requirements (deferred to next milestone)

- Analytics cookieless (Plausible) no hub — sem cookie banner
- Entrance animations no hub (motion/react) — após hub validado em produção
- og:image dinâmico via Satori (build-time) — quando o hub mudar frequentemente
- WhatsApp social link — configurar número E.164 real e reativar

## Out of Scope

- Separar em múltiplos repositórios — monorepo é a abordagem correta para este volume
- Subdomínios por curso (`vm.mentoria...`) — complexidade de DNS desnecessária
- Formulário ou email capture no hub — pertence às landing pages
- Redesign da landing page Deep Dive VM — conteúdo e design preservados
